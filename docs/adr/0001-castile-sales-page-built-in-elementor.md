# CASTILE sales page is built in Elementor, fully editable — unlike the Single Product page

The Single Product page (`woocommerce/single-product.php`) was deliberately kept out of Elementor (owner decision, 2026-07-27): it's plain PHP with WordPress Customizer style controls, because Elementor's drag-and-drop wasn't a good fit for that page's complex custom behavior. The new CASTILE sales page — a 24-section, high-fidelity, scroll-animated marketing page recreated from a Claude Design handoff — has similar complexity, but here the owner explicitly asked for the opposite: every field on the page editable in Elementor.

**Decision**: Build the CASTILE sales page as a genuine Elementor page (native widgets for all static content — headings, copy, images, proof cards, FAQ), so the owner/marketing team can self-serve edits without a developer. The one exception is the buying block (scent × size selector + Add to Cart), which stays code-driven since it's bound to live WooCommerce product/price/stock data that can't be represented as static Elementor fields.

**Trade-off accepted**: exact reproduction of the design's animation timings/easing (scroll-triggered count-ups, staggered mask reveals) may need supplementary scoped CSS/JS rather than being 100% stock Elementor Motion Effects — and that CSS/JS is coupled to Elementor's generated markup, so restructuring sections later in the editor can require re-pointing selectors. Chosen anyway because the priority for this specific page is marketing self-service editability, not the architectural consistency the Single Product page optimized for.
